  <name>Task 1: Add tx_index schema and CRUD functions to block_index_db</name>
  <files>include/block_index_db.h, src/storage/block_index_db.c</files>
  <action>
Add tx_index infrastructure to the existing block_index_db module. This follows the exact same patterns already used for the `blocks` table (prepared statements, mutex-protected access, db_exec/db_prepare/db_step wrappers).

**In block_index_db.h:**

1. Add four new prepared statement fields to `block_index_db_t`:
   - `db_stmt_t txindex_insert_stmt` — INSERT OR REPLACE INTO tx_index
   - `db_stmt_t txindex_lookup_stmt` — SELECT block_hash, file_index, file_pos FROM tx_index WHERE txid = ?
   - `db_stmt_t txindex_delete_block_stmt` — DELETE FROM tx_index WHERE block_hash = ?

2. Declare four new functions:
   - `echo_result_t txindex_insert(block_index_db_t *bdb, const hash256_t *txid, const hash256_t *block_hash, uint32_t file_index, uint32_t file_pos)` — insert one tx row
   - `echo_result_t txindex_lookup(block_index_db_t *bdb, const hash256_t *txid, hash256_t *block_hash_out, uint32_t *file_index_out, uint32_t *file_pos_out)` — lookup by txid, returns ECHO_ERR_NOT_FOUND if absent
   - `echo_result_t txindex_delete_by_block(block_index_db_t *bdb, const hash256_t *block_hash)` — delete all tx_index rows for a block hash (DONE is success even if zero rows)
   - `echo_result_t txindex_insert_block(block_index_db_t *bdb, const hash256_t *block_hash, const block_t *block, uint32_t file_index, uint32_t file_pos)` — convenience: iterate block->txs, compute txid for each via tx_compute_txid, call txindex_insert for each

**In block_index_db.c:**

1. In the `create_schema` function (or equivalent schema creation path), add:
   ```sql
   CREATE TABLE IF NOT EXISTS tx_index (
       txid       BLOB PRIMARY KEY,
       block_hash BLOB NOT NULL,
       file_index INTEGER NOT NULL,
       file_pos   INTEGER NOT NULL
   );
   CREATE INDEX IF NOT EXISTS idx_txindex_block ON tx_index(block_hash);
   ```
   Use `db_exec(db, ...)` following the exact pattern of the existing `CREATE TABLE IF NOT EXISTS blocks` statement.

2. In the prepared statement initialization path (where `lookup_hash_stmt`, `insert_stmt`, etc. are prepared), add:
   - `db_prepare(&bdb->db, "INSERT OR REPLACE INTO tx_index (txid, block_hash, file_index, file_pos) VALUES (?, ?, ?, ?)", &bdb->txindex_insert_stmt)`
   - `db_prepare(&bdb->db, "SELECT block_hash, file_index, file_pos FROM tx_index WHERE txid = ?", &bdb->txindex_lookup_stmt)`
   - `db_prepare(&bdb->db, "DELETE FROM tx_index WHERE block_hash = ?", &bdb->txindex_delete_block_stmt)`

3. In `block_index_db_close`, add `db_stmt_finalize` calls for all three new prepared statements.

4. In `block_index_db_checkpoint`, add `db_stmt_reset` calls for all three new prepared statements (same pattern as existing statements — reset before WAL checkpoint).

5. Implement `txindex_insert`: Lock mutex, reset stmt, bind txid->bytes (32 bytes blob param 1), bind block_hash->bytes (32 bytes blob param 2), bind file_index as int64 param 3, bind file_pos as int64 param 4, step, unlock. Return ECHO_OK if step returns ECHO_DONE. Follow the exact pattern in the research (Example 1).

6. Implement `txindex_lookup`: Lock mutex, reset stmt, bind txid->bytes param 1, step. If step returns ECHO_OK (row found), read column 0 as blob → memcpy into block_hash_out->bytes, column 1 as int64 → file_index_out, column 2 as int64 → file_pos_out. If step returns ECHO_DONE → return ECHO_ERR_NOT_FOUND. Unlock. Follow research Example 2.

7. Implement `txindex_delete_by_block`: Lock mutex, reset stmt, bind block_hash->bytes param 1, step. Unlock. Return ECHO_OK regardless of whether rows were deleted (ECHO_DONE means success). Follow research Example 3.

8. Implement `txindex_insert_block`: Iterate `block->txs[i]` for i in `0..block->tx_count`. For each tx, call `tx_compute_txid(&block->txs[i], &txid)` to get the non-witness txid. Then call `txindex_insert(bdb, &txid, block_hash, file_index, file_pos)`. If any insert fails, log warning and continue (best-effort; do not abort the entire block). Return ECHO_OK if all succeeded, or the last error code if any failed.

**Important details:**
- Store txid in internal byte order (as returned by tx_compute_txid). The RPC layer's rpc_parse_hash already converts display-order hex to internal order. Consistent byte order prevents lookup failures (Pitfall 4 from research).
- Use INSERT OR REPLACE to handle edge cases where a txid might appear in two blocks during a rapid reorg sequence.
- The block_hash index enables O(block_tx_count) deletes during reorg instead of full table scan.
- Include `tx.h` in block_index_db.c for `tx_compute_txid` and the `block_t` type (or include `block.h` which already includes `tx.h`).

Add txindex population after consensus_apply_block succeeds and the block index status has been updated:

```c
/*
 * Step 3: Populate transaction index.
 *
 * Index all transactions in this block so getrawtransaction can look them up.
 * The file position comes from the block_index_db entry (set by node_store_block
 * which runs before node_apply_block in the confirmation path).
 */
if (node->block_index_db_open) {
    block_index_entry_t bentry;
    echo_result_t idx_res = block_index_db_lookup_by_hash(
        &node->block_index_db, &block_hash, &bentry);
    if (idx_res == ECHO_OK && bentry.data_file >= 0) {
        idx_res = txindex_insert_block(
            &node->block_index_db, &block_hash, block,
            (uint32_t)bentry.data_file, bentry.data_pos);
        if (idx_res != ECHO_OK) {
            log_warn(LOG_COMP_DB,
                     "txindex insert failed for block at height %u: %d",
                     height, idx_res);
        }
    } else if (idx_res == ECHO_OK && bentry.data_file < 0) {
        log_debug(LOG_COMP_DB,
                  "skipping txindex for block %u: not yet stored on disk",
                  height);
    }
}
```

**Key detail from Pitfall 1:** The file position is NOT available from the block struct itself — it must be looked up from block_index_db. `node_store_block` records (data_file, data_pos) earlier in the pipeline.
