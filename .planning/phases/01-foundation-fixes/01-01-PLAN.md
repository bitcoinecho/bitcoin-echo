**chaser_validate.c — INFR-02: Wire real block hash in CHASE_CHECKED path**

At `chaser_validate.c:509-527`, the CHASE_CHECKED handler declares `uint8_t hash[32] = {0}` and submits it without ever looking up the real hash. The CHASE_BUMP/START path (lines 486-487) already calls `node_load_block_at_height()` which returns the real hash — the CHASE_CHECKED path must do the same.

Before the `chaser_validate_submit()` call in the CHASE_CHECKED handler, add:

1. Get the block index DB handle via `node_get_block_index_db(chaser->base.node)` (or equivalent accessor — read the file to find the exact API)
2. Call `block_index_db_lookup_by_height(bdb, height, &entry)` to retrieve the entry
3. If lookup succeeds (`== ECHO_OK`), `memcpy(hash, entry.hash.bytes, 32)`
4. If lookup fails, log a warning: `log_warn(LOG_COMP_SYNC, "chaser_validate: no index entry for height %u", height)` and proceed with the zero hash as fallback

Include `"block_index_db.h"` if not already present. Read the actual struct field names from the header — research says `entry.hash.bytes` but verify before writing.
