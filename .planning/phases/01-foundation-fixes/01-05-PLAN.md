**Step 1: Calibrate the threshold**

Read `include/download_mgr.h` to find `DOWNLOAD_MIN_RATE_BYTES_PER_SEC` (line ~53 per research, currently 3072 = 3 KB/s).

Calibrate based on Bitcoin Core's approach:
- Bitcoin Core uses a stall timeout of 2 seconds for block downloads and a minimum download speed check
- Bitcoin Core's `nMinExpectedRate` is effectively about 1024 bytes/sec (1 KB/s) for initial assessment, with dynamic adjustment
- For Echo's headers-first IBD with 64-block batches, consider: early blocks (pre-2012) average ~250 bytes, modern blocks average ~1-2 MB, SegWit blocks can reach ~2-4 MB
- A fixed threshold must handle both regimes: too high evicts peers that are fine for early blocks, too low keeps peers that stall on large blocks

**Recommended approach:** Use a conservative fixed threshold around 1024-2048 bytes/sec (1-2 KB/s) with the understanding that the grace period and stall detection handle the modern-block regime. Bitcoin Core uses stall detection (no progress for N seconds) as the primary mechanism, not minimum rate.

Set the constant with a detailed comment:

```c
/**
 * Minimum acceptable download rate for peer eviction (bytes/sec).
 *
 * Calibration rationale:
 * - Bitcoin mainnet blocks range from ~250 bytes (early chain, 2009-2012) to
 *   ~2-4 MB (modern SegWit/Taproot blocks, 2024+)
 * - Bitcoin Core uses stall detection (no progress for 2s) as primary mechanism,
 *   with minimum rate as secondary check
 * - A 1 KB/s threshold accommodates early-chain peers (250-byte blocks arrive
 *   well above this rate) while flagging truly stalled connections
 * - The stall timeout (DOWNLOAD_STALL_TIMEOUT_MS) handles the large-block case:
 *   a peer receiving a 2 MB block at any rate above 0 won't hit rate eviction,
 *   but will hit stall eviction if no data arrives for the timeout period
 * - This value is conservative; aggressive eviction risks network isolation
 *   during IBD when peer count is low
 *
 * Measurement: Based on Bitcoin Core nMinExpectedRate behavior and mainnet
 * block size distribution analysis. Re-evaluate after first full mainnet IBD.
 */
#define DOWNLOAD_MIN_RATE_BYTES_PER_SEC  1024  /* 1 KB/s — conservative */
```

If the existing value (3072) is already reasonable and the comment just needs calibration documentation, keep it and add the rationale comment. Use your judgment on the exact value — the documentation is the critical deliverable per user decision.
