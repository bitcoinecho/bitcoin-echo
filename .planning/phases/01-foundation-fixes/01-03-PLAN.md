<objective>
Fix chainwork storage to use big-endian byte order so SQLite's bytewise comparison correctly selects the highest-work chain.

Purpose: The block index database stores chainwork as a 32-byte blob. SQLite compares blobs bytewise (most-significant byte first). Currently chainwork is stored in little-endian (LSB first), meaning SQLite's comparison produces wrong ordering. This silently corrupts fork selection — the node may follow a lower-work chain. The fix is byte-reversal at the exact insert/read boundary in block_index_db.c. No in-memory arithmetic changes.

Output: block_index_db.c updated with big-endian serialization and corrected best-chain query.
</objective>

**Add byte-reversal helper functions** near the top of `block_index_db.c` (static, file-scoped):

```c
/**
 * Convert work256_t (little-endian internal format) to big-endian blob for SQLite storage.
 *
 * SQLite compares BLOBs bytewise (most-significant byte first). Storing chainwork
 * as big-endian ensures ORDER BY chainwork DESC correctly selects the highest-work chain.
 * The in-memory work256_t format (little-endian, byte[0]=LSB) is unchanged.
 *
 * Parameters:
 *   work   - Source chainwork in little-endian internal format
 *   be_out - Destination 32-byte buffer for big-endian blob
 */
static void work256_to_be_blob(const work256_t *work, uint8_t *be_out) {
    for (int i = 0; i < 32; i++) {
        be_out[i] = work->bytes[31 - i];
    }
}

/**
 * Convert big-endian blob from SQLite back to work256_t (little-endian internal format).
 *
 * Parameters:
 *   be_in - Source 32-byte big-endian blob from database
 *   work  - Destination work256_t in little-endian internal format
 */
static void be_blob_to_work256(const uint8_t *be_in, work256_t *work) {
    for (int i = 0; i < 32; i++) {
        work->bytes[i] = be_in[31 - i];
    }
}
```
