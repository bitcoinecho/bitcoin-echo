Upgrade rpc_submitblock from stub to production by adding the IBD guard and peer announcement after block acceptance.

Purpose: A mined block submitted via RPC must be rejected during IBD (to prevent building on incomplete chains) and must be announced to the network after acceptance (so the block propagates). The existing stub correctly parses, validates, and applies the block but is missing both of these behaviors.

Output: A working submitblock RPC that correctly guards against IBD and announces accepted blocks to peers.

Make two surgical additions to the existing `rpc_submitblock` function:

**A. IBD guard (after NULL checks, before hex parameter parsing):**
```c
/* Reject block submission during IBD — miners must not build on incomplete chain.
 * Returns RPC error -28 via the ECHO_ERR_INVALID_STATE convention (see rpc_execute_single). */
if (node_is_ibd_mode(node)) {
  return ECHO_ERR_INVALID_STATE;
}
```
This uses the same `ECHO_ERR_INVALID_STATE -> -28` mapping established in Plan 06-01's Task 1.

**B. Peer announcement after successful node_apply_block:**
After `res = node_apply_block(node, &block)` succeeds (before `block_free`), compute the block hash and announce:
```c
res = node_apply_block(node, &block);

if (res == ECHO_OK) {
  /* Announce accepted block to peers so it propagates to the network.
   * node_announce_block_to_peers skips announcement during IBD internally,
   * but we've already guarded against IBD above, so this always announces. */
  hash256_t block_hash;
  block_header_hash(&block.header, &block_hash);
  node_announce_block_to_peers(node, &block_hash);
}

block_free(&block);
```

IMPORTANT: The `block_header_hash` call and `node_announce_block_to_peers` call MUST happen before `block_free(&block)` since they reference `block.header`. Move `block_free(&block)` to after the announcement logic.

The rest of the function (error paths for validation failure, apply failure, success null response) stays exactly as-is.

Do NOT change the function signature. Do NOT add new files.
