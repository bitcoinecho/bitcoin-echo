<task type="auto">
  <name>Task 2: Upgrade rpc_getblocktemplate to production BIP-22/BIP-145</name>
  <files>src/app/rpc.c</files>
  <action>
Replace the existing `rpc_getblocktemplate` function body with a production implementation. The function signature stays the same. Required changes:

**A. IBD guard (top of function, after NULL checks):**
```c
if (node_is_ibd_mode(node)) {
  return ECHO_ERR_INVALID_STATE;
}
```

**B. Real MTP computation for mintime (replace the rough estimate):**
Copy the MTP computation pattern from `rpc_getblockchaininfo` (already in the same file, ~lines 1662-1695). Walk up to 11 blocks back from `tip_index` through `block_index_map`, collect timestamps, insertion-sort, take median. Then set `mintime = mtp + 1` (BIP-22 requires strictly greater than MTP). Use `node_get_consensus(node)` (non-const) for `consensus_get_chainstate` access — this pattern was established in Phase 05-02.

**C. Correct difficulty bits (replace DIFFICULTY_POWLIMIT_BITS placeholder):**
Use `consensus_build_validation_ctx()` to get the correct `bits` for the next block height:
```c
full_block_ctx_t block_ctx;
full_block_ctx_init(&block_ctx);
echo_result_t ctx_res = consensus_build_validation_ctx(consensus, next_height, &block_ctx);
uint32_t bits;
if (ctx_res == ECHO_OK) {
  difficulty_compute_next(&block_ctx.difficulty_ctx, &bits);
} else {
  bits = tip_index->bits; /* fallback: use tip bits */
}
```
Note: `consensus_build_validation_ctx` takes a `const consensus_engine_t*` — use the const consensus already in scope. This handles retarget boundaries correctly.

**D. Add `"rules": ["segwit"]` field:**
After the `"weightlimit"` field, append:
```c
json_builder_append(builder, ",\"rules\":[\"segwit\"]");
```

**E. Witness commitment computation:**
After selecting transactions and before closing the JSON object, compute the witness commitment:

1. Allocate wtxid array with `calloc(1 + selected_count, sizeof(hash256_t))` — index 0 stays all-zeros (coinbase wtxid per BIP-141). CRITICAL: use `calloc` not `malloc` to ensure zero-initialization.
2. For each selected transaction `i` (0-based), call `tx_compute_wtxid(&selected[i]->tx, &wtxids[i + 1])`.
3. Compute witness merkle root: `merkle_root(wtxids, 1 + selected_count, &witness_root)` — use `merkle_root()` directly (NOT `merkle_root_wtxids()` which expects a tx_t array with coinbase).
4. Compute commitment: create a zero-initialized `hash256_t nonce` (32 zero bytes, standard witness nonce), then `witness_commitment(&witness_root, &nonce, &commitment)`.
5. Build 38-byte scriptPubKey: `0x6a 0x24 0xaa 0x21 0xa9 0xed <32-byte-commitment>`.
6. Emit as: `"default_witness_commitment":"<76-hex-chars>"` using `json_builder_hex(builder, script, 38)`.
7. Free the wtxid array.

If `selected_count == 0` (empty mempool), still emit the witness commitment — a template with zero transactions should still have the correct commitment (just the coinbase-only merkle root = 32 zero bytes).

**F. Per-transaction BIP-145 fields:**
In the transaction loop, add these fields to each tx object:
- `"hash"` (wtxid): format `entry->wtxid` via `rpc_format_hash` and emit as string.
- `"weight"`: use `tx_weight(&entry->tx)` instead of `entry->vsize * 4`.
- Keep existing `"txid"`, `"data"`, `"fee"` fields.

**Includes:** Add `#include "block_validate.h"` if not already present (for `full_block_ctx_t`, `difficulty_compute_next`). Add `#include "merkle.h"` if not present (for `merkle_root`, `witness_commitment`).

Do NOT change the function signature. Do NOT add new files.
