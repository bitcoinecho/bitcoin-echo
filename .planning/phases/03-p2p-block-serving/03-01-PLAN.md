  <name>Task 1: Add SERVICE_NODE_WITNESS to version message services bitmask</name>
  <files>src/app/node.c</files>
  <action>
Fix all three `peer_send_version` call sites in `node.c` (lines 2937, 2961, 3329) to use named constants instead of literal `1`/`0`.

Current pattern at each site:
```c
uint64_t services = node_is_pruning_enabled(node) ? 0 : 1;
peer_send_version(peer, services, (int32_t)our_height, true);
```

Replace with:
```c
uint64_t services = SERVICE_NODE_WITNESS;  /* Always: we speak SegWit protocol */
if (!node_is_pruning_enabled(node)) {
  services |= SERVICE_NODE_NETWORK;        /* Full block history if not pruned */
}
peer_send_version(peer, services, (int32_t)our_height, true);
```

Update the comment at the first call site (line 2935-2936) from:
```c
/* Service flags: NODE_NETWORK (1) only if we're not pruned
 * Pruned nodes cannot serve historical blocks */
```
To:
```c
/* Service flags: Always advertise NODE_WITNESS (we speak SegWit protocol).
 * Add NODE_NETWORK only if not pruned (full block history available). */
```

All three sites use the identical pattern — apply the same fix at each. The constants are defined in `protocol.h`:
- `SERVICE_NODE_NETWORK` = `(1 << 0)` = 1
- `SERVICE_NODE_WITNESS` = `(1 << 3)` = 8

**Why NODE_WITNESS for pruned too:** NODE_WITNESS means "I understand the SegWit wire protocol", not "I have all historical blocks". A pruned node can and should advertise it. Bitcoin Core does the same.

Do NOT use numeric literals (9, 8, 1, 0) — always use the named constants.
